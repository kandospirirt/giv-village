3.2 SPRYNTER — Scheduled Mini-Bus SaaS
What It Is
Sprynter is a mobile-first platform for scheduled mini-bus transport in Ghana and other African countries. It combines the reliability of public transit with the flexibility of ride-hailing.

Two Apps
App	User	Features
Sprynter Passenger	Riders	Browse routes, book guaranteed seat, pay digitally, track bus in real-time, request on-demand pickup
Sprynter Operator	Bus drivers/owners	Manage routes, view bookings, collect payments digitally, receive maintenance alerts
How It Works
Feature	Description
Station-based routing	Passengers board at fixed stations (Circle Station, Tema Station, etc.) — no free-text search. Station picker with autocomplete + GPS-proximity for boarding and dropoff.
Scheduled routes	Standard buses run set routes at scheduled times — passengers book guaranteed seats per timeslot
GPS live tracking	Buses stream GPS positions every 5s; riders see real-time bus position on map with ETA to next station
On-demand LUXURY	Luxury tier works Uber-style: rider requests pickup via GPS → nearest luxury vehicle matched → 15-second driver acceptance window → fare locked
Guaranteed seating	Every passenger has a reserved seat — no standing, no squeezing
Digital payments	Mobile money, card, cash — all accepted
Price per ride	Tier-based pricing (STANDARD 1.0x / COMFORT 1.15x / LUXURY 1.8x) — see Vehicle Tiers table above
Bus ownership	Operators buy buses from Sprynter (partner with manufacturer) — full payment or installment
Servicing	Vehicle servicing is included in the installment package
Remote lock	If operator stops paying installments, Sprynter can lock the bus remotely
Commission	Free for operators for the first year, then 25% commission on every ride
Vehicle Tiers
Sprynter offers two vehicle classes with differentiated fare pricing:

Tier	Vehicle	Price Multiplier	Fare Formula Example (10 km trip)
STANDARD	Toyota Voxy / Noah Hybrid	1.0x base fare	GHS 50 + (10 × GHS 2) = GHS 70
COMFORT	GAC M6 (8-seat)	1.15x comfort fare	GHS 70 × 1.15 = GHS 80.50
LUXURY	Toyota Alphard Hybrid	1.8x premium	GHS 50 + (10 × GHS 2) × 1.8 = GHS 126

Fare Formula: GHS 50 base + (GHS 2/km for first 10 km, then GHS 1/km beyond) × tier_multiplier
Passengers select their tier when booking — the rider app displays dynamic pricing per class side by side. Fleet management lets admins assign each vehicle to a tier and configure its multiplier.

Target Operators
Sprynter targets the next generation of drivers — young entrepreneurs who want to own and operate a transport business but need:

A reliable vehicle
A booking system to fill seats
Maintenance support
Payment infrastructure

EXPANSION ADDENDUM — Three Pillars for Ecosystem Scale
=============================================================================

These three features expand Pricewards from a marketplace into a self-contained fashion production platform. They address the three biggest gaps in our current foundation: designer acquisition (Fashion Shows), manufacturing capacity (Partner Collaboration), and design capability (FreeSewing-like Designer Studio).

PILLAR 1: Fashion Show Recruitment
──────────────────────────────────────────────────
Problem: The current designer onboarding relies on manual admin approval. This limits scale and doesn't create marketing moments or community momentum. We need a recruitment channel that attracts designers organically while creating public-facing events.

Solution: Organize fashion shows as the primary designer recruitment channel. Designers apply to shows with portfolio submissions, selected designers are auto-approved into the platform, and shows become recurring brand-building events.

Architecture:
• FashionShow model — event CRUD with status lifecycle (DRAFT → OPEN → CLOSED → COMPLETED), location, deadline, gallery
• DesignerApplication model — application form (portfolio images, bio, signature styles, experience), status tracking (SUBMITTED → UNDER_REVIEW → SELECTED/WAITLIST/REJECTED)
• ShowJudging model — judge scoring panel with aggregate scores and feedback
• Post-show auto-onboarding: selected applicants get auto-created DesignerProfile + Stripe Connect onboarding URL

New routes: /fashion-shows, /fashion-shows/[slug], /show/apply/[id] (public); admin show creation/judging panel; designer-dashboard "applications" section.

Impact: Creates recurring brand moments, scales designer acquisition beyond manual outreach, builds public narrative around Pricewards as a platform that discovers talent (not just hosts it).

Timeline: 4 sprints (12-20 days for one engineer)

PILLAR 2: Manufacturing Partner Collaboration (Woodin, GTP & others in Ghana)
──────────────────────────────────────────────────
Problem: The current Fabric model is a read-only catalog managed via admin. There is no concept of manufacturing partner relationships — no supplier profiles, no quote workflow, no partner-specific fabric catalogs, and no production capacity booking.

Solution: Add ManufacturingPartner as a new ecosystem entity type (alongside Designer) with full lifecycle: registration → profile → capabilities → fabric catalog → production requests → quoting → fulfillment.

Architecture:
• ManufacturingPartner model — name, type (CLOTHING_PRODUCER | PRINT_HOUSE | FABRIC_SUPPLIER | CUT_AND_SEW), location, capabilities, capacity, Stripe Connect for platform-to-partner payouts
• PartnerFabric model — partner-specific fabric catalog with pricing per meter, linked to ManufacturingPartner
• ManufacturerOrder model — designer submits design → production partner quotes → accepts → tracks production timeline (quoteStatus: PENDING → QUOTED → ACCEPTED → REJECTED)
• Existing Fabric model extended with manufacturerId relation
• New role: MANUFACTURING_PARTNER in User.role enum

Hub dashboard gets new tabs: "Manufacturing Partners", "Partner Orders", "Partner Payouts". Designer dashboard gets "production" section for tracking assigned manufacturers and quote status.

Impact: Turns fabric catalog from static reference into an active procurement system. Enables Woodin, GTP, and other Ghanaian print houses to become active platform participants — not just references but quoted, ordered, tracked partners.

Timeline: 5 sprints (15-25 days for one engineer)

PILLAR 3: Designer Studio — FreeSewing-like Design Tool
──────────────────────────────────────────────────
Problem: Designers currently upload static portfolio images. They have no built-in tool to create designs on the platform. This means Pricewards can't serve designers who want to prototype before committing to production, and it misses a key differentiator vs. competitors (who rely entirely on designer-provided designs).

Solution: A FreeSewing-like design tool embedded in the designer dashboard. Designers input body measurements → get base garment shapes → customize style options (neckline, sleeve type, length, fit) → apply print overlays from Woodin/GTP partner catalogs → export as SVG/PDF spec sheets for production.

Architecture:
• paper.js canvas engine (superior to fabric.js for vector pattern math — bezier curves, boolean path ops, transform matrices essential for garment pattern pieces)
• DesignerPatternConfig model — stores baseGarment type, bodyMeasurements, svgPattern (structured JSON of SVG path data per garment piece), styleConfig (neckline, sleeveType, length, fit), printOverlay (partner fabric + repeat pattern)
• PatternEngine library: measurements → base shape calculation → real-time SVG updates → export

MVP scope: Single garment type (dress or top). Measurement input form → body-proportional rectangle generation → style panel dropdowns → print overlay from PartnerFabric catalog → save to designer dashboard → export as SVG + measurement spec sheet.

5 sprints total:
• Sprint 3a: Measurement form + base shape generation + paper.js canvas shell
• Sprint 3b: Style config panel (neckline/sleeve/length → real-time SVG updates)
• Sprint 3c: Print overlay system (PartnerFabric catalog → repeat pattern overlay)
• Sprint 3d: Save/design gallery/export (SVG download + spec sheet JSON/PDF)
• Sprint 3e: Multi-garment templates (top, skirt, pants). Responsive canvas.

Impact: Turns designers from passive catalog contributors into active platform users who create on Pricewards. Creates lock-in (designers invest their tools here), enables faster design iteration, and bridges the gap between sketch and production spec.

Timeline: 5 sprints (15-25 days for one engineer)

Phase 0 (Schema Foundation) → Phase 1 (Fashion Shows)
Phase 0 → Phase 2 (Manufacturing Partners) → Phase 3c (Print overlays require PartnerFabric catalog)
Phase 0 → Phase 3a/b (Measurements + shapes independent of Phase 2)
